`mew-mobile-core` holds all iroh and daemon protocol logic in Rust and exposes
typed events to the `mew-ios` SwiftUI client through UniFFI.

## Prerequisites

Install Xcode with the iOS 26 SDK and the Rust iOS targets:

```sh
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
```

## Build the mobile core

:::caution
With `libc` 0.2.191 in `Cargo.lock`, a fresh iOS build fails because `netdev`
0.46.3 references `libc::in6_ifreq` and `netwatch` 0.19.3 references BSD
routing symbols such as `RTM_GET2` and `RTF_IFSCOPE`, which iOS omits. macOS
daemon builds succeed with the same lockfile.
:::

```sh
just ios-core
```

`just ios-core` builds release static libraries for `aarch64-apple-ios` and
`aarch64-apple-ios-sim`, generates Swift bindings via `uniffi-bindgen`, and
packages both slices into an XCFramework:

- `mew-ios/MewMobileCore/Sources/MewMobileCore/mew_mobile_core.swift`: generated
  Swift bindings.
- `mew-ios/MewMobileCore/XCFramework/mew_mobile_core.xcframework`: gitignored
  universal binary regenerated by `just ios-core`.

### SwiftPM package

`mew-ios/MewMobileCore/` defines two targets:

- `mew_mobile_coreFFI`: binary target wrapping the XCFramework and C modulemap.
- `MewMobileCore`: Swift source target exporting `MobileCore`, `CoreEvent`,
  `CoreListener`, and related generated types.

Verify the SwiftPM package with `xcodebuild` (`swift build` fails on macOS
because the XCFramework carries iOS slices only):

```sh
cd mew-ios/MewMobileCore
xcodebuild -scheme MewMobileCore \
  -destination 'generic/platform=iOS Simulator' build
```

## Build the iOS app

```sh
cd mew-ios
xcrun simctl list devices available
xcodebuild -project mew.xcodeproj -scheme mew \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```

Or run `just ios-test` from the repository root (targets `name=iPhone 17`). Use
an available iOS 26 simulator from `simctl`, or open `mew.xcodeproj` in Xcode.
Keep edits in the checked-in `mew.xcodeproj`: `project.yml` does not include
the test targets or package pins, so regenerating it drops them.

## Architecture

### Identity and connection model

Each install generates one iroh `SecretKey` on first launch and stores the 32
raw bytes in the iOS keychain under
`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` (excluded from iCloud sync).
Settings displays the public NodeId for pairing.

`MobileCore` opens one iroh connection per daemon:

1. `endpoint.connect(node_id, MEW_ALPN)` then `open_bi()`, followed by a
   WebSocket handshake over the QUIC stream.
2. Send `Ping` and check `Pong { version, protocol_version }` for version skew.
3. Switch chats over the same connection with `AttachSession`.
4. Receive `SessionAlert` across any daemon session regardless of attachment.
5. Connect lazily to background daemons unless per-daemon background keepalive
   is enabled.

### Reconnect and lenient codec

Unexpected disconnects retry with jittered exponential backoff (1s, 2s, 4s, up
to 30s), reattach, and load the newest `SessionHistoryPage` (older pages load on
demand).

Because `mew-protocol` enums reject unknown variants, `codec.rs` inspects each
frame as `serde_json::Value` first and logs/drops unrecognized variants so a
newer daemon will not break an older iOS client.

### State assembly, files, and coalescing

- **Part assembly**: `state.rs` folds `Provider` stream events into messages and
  replaces delta-accumulated parts whenever an authoritative `PartUpdated`
  arrives.
- **File browser**: `list_dir(daemon_id, session_id, path?)` sends
  `ClientMessage::ListDir` and converts `ServerMessage::DirListing` into
  `CoreEvent::DirListing` (`DirEntry { name, is_dir, size }`).
- **Text coalescing**: `lib.rs` batches `TextDelta` updates on a 16ms tick
  before crossing the UniFFI/ObjC boundary.
- **Daemon management**: `read_daemon_settings`, `save_session_defaults`,
  `reset_session_defaults`, and `revoke_device` use request IDs, expire after 5
  seconds or on disconnect, and require full-control remote access. Defaults
  persist in `new-chat-defaults.json` under the session directory.

### Swift navigation and session ownership

Swift tracks the selected daemon and open chat in the root navigation path,
validates restored session IDs against daemon metadata, and retains per-chat
drafts in memory. Create and attach requests track actual sent operations and
use typed `SessionOperationFailed` errors for scoped retry; background settings
queries refresh catalogs without shifting the active connection.

## Testing

```sh
# Fast library unit tests (no network)
cargo test -p mew-mobile-core --lib

# Real iroh integration tests (~45s each; uses multi_thread tokio runtime)
cargo test -p mew-mobile-core --features test-harness --test m0_spike -- --nocapture
cargo test -p mew-mobile-core --features test-harness --test m1_integration -- --nocapture

# Cross-crate mobile and daemon test suite
cargo test -p mew-client-core -p mew-mobile-core -p mew-protocol \
  -p mew-diff -p mew-session --all-targets --features mew-mobile-core/test-harness
cargo test -p mew-daemon --features iroh
cargo clippy -p mew-mobile-core --all-targets --features test-harness -- -D warnings
cargo clippy -p mew-daemon --all-targets --features iroh -- -D warnings
just ios-core
just ios-test
```

`AppNavigationTests` and `AppStoreEventHandlingTests` test navigation,
cross-daemon isolation, drafts, confirmed settings, and recovery races using
isolated preference suites.

### Physical-device checklist

Before shipping a build, test on a physical iPhone:

- Pair with a fresh QR invite, an expired invite, and a reused invite. Connect
  two daemons, filter the timeline, switch chats, verify **Offline** labels, and
  confirm creating from **All** uses the selected machine.
- Save and reset new-chat defaults, revoke another device and the phone itself,
  and verify older daemons and read-only connections leave active chats intact.
- Send and cancel turns, page older history while streaming, background and
  reopen the app, and test pending permission/question sheets across reconnects.
- Search and expand tool groups (and check VoiceOver, dynamic type, and reduced
  motion), inspect running workers and chunked job output across reconnects, and
  refresh workspace diffs across light/dark and narrow layouts.

## Adding a CoreEvent variant

1. Add the variant to `CoreEvent` in `crates/mew-mobile-core/src/events.rs`.
2. Emit it from `translate_message` in `crates/mew-mobile-core/src/lib.rs`.
3. Regenerate bindings and the XCFramework with `just ios-core`.
4. Handle the variant in `AppStore.handleEvent()` (`mew-ios/mew/AppStore.swift`).
5. Run `just ios-test` and commit the updated Swift bindings alongside the Rust
   change.

## Known issues

- The XCFramework builds `arm64` slices (device and Apple Silicon simulator)
  only; Intel Macs need `x86_64-apple-ios-sim` added to the build recipe.
- SwiftPM requires `module.modulemap` (handled by `just ios-core` in a
  temporary headers directory).
- `swift build` on macOS fails because the XCFramework contains no macOS slice;
  always test with `xcodebuild`.
